{# Participant details: a user research aid on every page (layouts/main.html). The facilitator enters the participant's first and last name and the organisation they work for or act for; the journeys' hooks then use them in place of the prototype's stand-in names (app/routes/research.js, participantOf in app/lib/research.js). It opens from the "Participant details" footer link or from `?participant` on any URL (the route sets `participantModal`). It is a native dialog element, styled apart from the service in _research-participant.scss so nobody takes a facilitator's box for part of GOV.UK; research-participant.js opens it as a modal over the page. Until it is opened the dialog waits in a template element, out of the page: its "First name" and "Last name" boxes would otherwise sit, hidden, beside the journey's own on the name pages (and in the tests' label lookups). Opened by the flag it is rendered straight into the page, open, so it shows without JavaScript too. On a journey for staff (`participant: staff` in its journey.yaml) the participant fills it in themselves, so it speaks to them: the staff header shows their name over their organisation. The markup is a macro because it is rendered in one of those two ways. Macros cannot see the template context in this nunjucks, so the participant, the page's URL (query string and all, so a previewed page comes back in preview) and whether it speaks to the participant are passed in. #} {% macro participantDialog(participant, returnTo, open, forStaff) %}
